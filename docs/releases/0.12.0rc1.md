# eyetrajectoriespy 0.12.0rc1

**Planned release candidate — not yet published**

`0.12.0rc1` is the planned first public candidate for native sparse
multivariate FPCA/joint PACE over two jointly observed planar coordinates.

This page is release-preparation material. The repository package identity
remains `0.11.0`, release readiness remains disarmed, and no GitHub Release,
tag, TestPyPI upload, or production-PyPI publication is created by the
RC-readiness decision.

## Frozen scientific surface

The planned candidate freezes the 0.12 scientific/API surface around:

- `SparseMFPCAResult`;
- `fit_sparse_mfpca()`;
- `sparse_mfpca_score_frame()`;
- `sparse_mfpca_reporting_text()`;
- `evaluate_sparse_mfpca_recovery()`.

The canonical estimator is the direct sparse block-covariance route. It fits a
vector mean, direct latent Cxx/Cxy/Cyy surfaces, defines
`Cyx(s,t)=Cxy(t,s)`, validates/repairs the full quadrature-weighted joint
operator under the declared PSD policy, computes one joint eigensystem, and
uses full-covariance joint PACE scores.

No alternate estimator becomes public during RC qualification.

## Scientific contracts frozen for the RC phase

The release candidate keeps the following contracts fixed:

- exactly two jointly observed coordinates with synchronized retained native
  timestamps;
- all latent xx, yy and xy covariance products use different time indices;
- Cxy is directional and is never self-symmetrized;
- public functional arrays use time-before-dimension convention;
- score observations use explicit time-major interleaved x/y ordering;
- joint PACE uses the full fitted joint covariance rather than a rank-K
  reconstruction;
- `measurement_error="diagonal"` requires two declared variances;
- `measurement_error="fixed_matrix"` requires a supplied finite symmetric PSD
  2x2 covariance matrix;
- invalid analyst-supplied measurement-error matrices fail rather than being
  projected;
- automatic bandwidth selection, automatic component selection, channel
  weighting, asynchronous coordinate-specific missingness, automatic
  cross-channel noise estimation, sparse multilevel decomposition and Bayesian
  sparse MFPCA remain outside 0.12.

## Qualification already completed before RC versioning

The pre-RC development line has completed all seven design gates:

1. direct joint operator/covariance/PACE implementation;
2. analytical/operator tests;
3. identification-aware known-truth planar recovery;
4. internal two-stage marginal-basis sensitivity;
5. external mGSFPCA 0.2.2 sensitivity;
6. separate public-estimator observation-process stress;
7. portability, documentation, examples, dedicated performance and complete
   cross-platform CI.

Known-truth qualification includes rho_xy = -0.6, 0, 0.3, 0.6 and 0.9, an
asymmetric directional Cxy truth, and a supplied correlated measurement-error
case. Tied truth eigenspaces are assessed by subspace geometry and
Procrustes-aligned score error instead of arbitrary component identity.

The two-stage and mGSFPCA evidence is sensitivity evidence only. It does not
claim exact equivalence or select an architecture winner.

Observation-process stress is threshold-free. Informative row-loss mechanisms
produce visible recovery changes but are not silently reclassified as
estimator defects or used to tune defaults.

The dedicated sparse-MFPCA performance evidence is a single-package,
environment-specific runtime/peak-memory envelope and makes no cross-package
speed claim.

## Exact-version qualification still required

The pre-RC evidence above is not relabelled as `0.12.0rc1` evidence.

After a separate version-alignment change establishes package identity
`0.12.0rc1`, the candidate must generate fresh exact-version evidence and
pass:

- package build and metadata consistency;
- Python 3.11–3.13 on Ubuntu, macOS and Windows;
- docs and executable examples;
- optional scikit-fda and FDApy sparse compatibility lanes;
- native sparse/PACE validation;
- sparse-MFPCA known-truth recovery and grid/ridge sensitivity;
- two-stage and mGSFPCA comparator sensitivity;
- public sparse-MFPCA observation-process stress;
- dedicated sparse-MFPCA performance envelope;
- general functional-simulation recovery/stress;
- release-readiness build, wheel/sdist fresh-install checks;
- complete exact-main qualification after merge.

Only after that exact-version matrix is green may a separate reviewed
governance change arm GitHub/PyPI publication.

## Installed-artifact qualification

The existing `installed-rc-qualification` workflow remains pinned to immutable
published `0.11.0rc1` until `0.12.0rc1` actually exists on production
PyPI. It must not be repointed before publication, because doing so would turn
an installed-artifact check into a guaranteed missing-version failure.

After publication, a follow-up installed-artifact qualification must install
exact `eyetrajectoriespy==0.12.0rc1` outside the repository checkout and
exercise the decision-relevant public 0.12 surfaces.
