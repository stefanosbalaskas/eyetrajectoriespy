# Independent-reference validation ledger

This ledger records validation against an analytical result or an
**independently represented/implemented** reference rather than only a
simulation generated by the same package.

The ledger is intentionally selective. The goal is to validate important
scientific contracts, not to duplicate every unit test.

## Required fields

Each entry should record:

- package estimator/API;
- reference implementation or analytical result;
- dataset/problem construction;
- expected quantity;
- numerical/statistical tolerance;
- CI test that enforces the comparison;
- supported platforms/backend versions;
- interpretation boundary.

## 0.56 candidate ledger

The next tranche should add a small number of high-value independent cases:

| Area | Candidate reference target | Quantity to compare |
|---|---|---|
| FPCA | analytical/small matrix eigendecomposition or independent FDA implementation | eigenvalues, subspace/reconstruction |
| Gaussian functional mixed effects | independently assembled marginal Gaussian likelihood or trusted scalar/basis special case | fixed effects, covariance/log-likelihood special case |
| Poisson exposure GEE | direct statsmodels stacked exposure model or analytically constructed constant-basis special case | coefficients, fitted rates/counts, robust covariance |
| DTW / discrete Fréchet | independently calculated toy paths with known optimum/path/bottleneck | distance and alignment/coupling |
| RQA | published/reference recurrence matrix and metric definitions | RR/DET/LAM and line counts under the exact convention |
| Transfer entropy | independently enumerated discrete probability table | TE value/support counts under declared histories |

Do not mark a case qualified merely because two functions inside
`eyetrajectoriespy` agree with each other. The reference representation or
implementation must be meaningfully independent of the code path under test.
